# 반도체 데이터 엔지니어링 — 반도체 설계·공정 AX 마스터 클래스

**파이썬을 활용한 반도체 데이터 분석과 업무 자동화**

이 저장소는 도서 『반도체 데이터 엔지니어링(가제)』(한빛아카데미)의 공식 실습 코드와 데이터 생성 스크립트를 제공합니다. 교재의 목차와 폴더 구조가 1:1로 대응하므로, 학습 중인 절의 코드를 바로 찾아 실행할 수 있습니다.

## AlphaChip_V2 프로젝트 세계관

이 책의 모든 실습은 하나의 시나리오로 이어집니다.

> 완전 자율주행 차량용 NPU **AlphaChip_V2**(3나노 EUV 공정)를 양산하던 중 원인 미상의 수율 급락이 발생했습니다. 설계와 레시피의 변경은 보고되지 않았는데, 로트가 진행될수록 불량률이 오릅니다. 중간에 잠시 내려간 구간도 있지만 후반부로 갈수록 크게 악화됩니다. 설계팀은 타이밍 슬랙이 무너진 경로를 확인했지만 그 칩이 언제 어디서 만들어졌는지 모르고, 공정팀은 장비 이력을 갖고 있지만 그때 만든 칩이 실제로 불량이 되었는지 알지 못합니다. 두 데이터가 서로 다른 시스템에 나뉘어 있기 때문입니다.

독자는 이 사태에 투입된 데이터 엔지니어로서 다섯 단계의 미션을 수행합니다.

| 단계 | 파트 | 미션 |
|---|---|---|
| ① 데이터 통합 | PART 1 | 흩어진 설계·공정 데이터를 파이썬으로 파싱해 정형 자산으로 만든다 |
| ② 관계 추적 | PART 2~3 | 로트·웨이퍼·장비 축으로 나누고 시각화해 불량이 몰린 곳과 함께 움직이는 공정 조건을 추적한다 |
| ③ 자산화 | PART 3 | 분석 결과를 데이터베이스와 자동 생성 리포트로 남긴다 |
| ④ 예측 | PART 4 | 설계 지표를 회귀로 예측하고, 센서 이력으로 이후 구간의 공정 이상 위험을 예측한다 |
| ⑤ AI 코파일럿 | PART 5 | 에러 코드에 맞는 조치 절차를 가상 장비 매뉴얼에서 찾아 주는 RAG 챗봇을 만든다 |

> **스포일러 안내**
> 수율 급락과 함께 움직이는 요인은 6장에서 독자가 직접 데이터로 추적하도록 설계되어 있습니다. 이 저장소의 문서와 1~5장 코드의 주석은 그 결과를 미리 밝히지 않습니다. `data/data_generator.py`에는 데이터를 만드는 관계식이 그대로 들어 있으므로, 스스로 찾아보고 싶다면 6장을 마친 뒤 열어 보기를 권합니다.

## 실습 환경 구축

의존성 충돌을 막기 위해 반드시 **파이썬 가상환경(venv)** 위에서 실행합니다. 교재의 표준 실습 환경은 **윈도우 + PowerShell**입니다. 도구 설치 화면은 [온라인 부록 A-1](docs/appendix-a1/README.md)에서 단계별로 안내합니다.

### 요구 사양

| 항목 | 사양 |
|---|---|
| OS | Windows 10 이상(표준 실습 환경) / Ubuntu 22.04 LTS 이상·macOS |
| Python | **3.14** (최소 3.12 이상) |
| IDE | Visual Studio Code (Python Extension, 원격 실습 시 Remote-SSH) |
| Database | SQLite3 (Python 표준 라이브러리 내장) |
| 형상 관리 | Git |

> numpy 2.5 이상이 Python 3.12 이상을 요구하므로, 3.10·3.11 환경에서는 `requirements.txt`의 조합을 그대로 설치할 수 없습니다.

### 설치 절차 (PowerShell)

```powershell
# 1) 저장소 클론
git clone https://github.com/aagicap/Semiconductor-AX-Masterclass.git
cd Semiconductor-AX-Masterclass

# 2) 가상환경 생성 및 활성화
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3) 의존성 설치
pip install -r requirements.txt

# 4) 설치 확인
python check_environment.py

# 5) 통합 데이터셋과 타이밍 리포트 생성
python data\data_generator.py
python data\log_generator.py

# 6) 공통 모듈 설치(4장부터 필요)
pip install -e .
```

macOS·리눅스에서는 2)의 활성화 명령을 `source .venv/bin/activate`로, 경로 구분자 `\`를 `/`로 바꿉니다.

`check_environment.py`가 가상환경 격리를 `PASS`로, 패키지를 모두 `OK`로 출력하면 준비가 끝난 것입니다. PowerShell에서 활성화 스크립트 실행이 막히면 부록 A-1의 실행 정책 항목을 참고합니다.

> **가상환경 폴더명은 반드시 `.venv`로 만듭니다.** `.vscode/settings.json`이 인터프리터 경로를 `.venv` 기준으로 고정해 두었기 때문에, `venv`나 `env` 같은 다른 이름을 쓰면 VS Code가 시스템 파이썬을 선택합니다. 이미 다른 이름으로 만들었다면 폴더를 지우고 다시 만드세요. 가상환경은 내부에 경로를 절대 경로로 기록하므로 이름만 바꾸거나 폴더를 옮기면 정상 동작하지 않습니다.

> **저장소를 갱신해 새 `ax_` 공통 모듈이 추가되면** `pip install -e .`를 다시 실행합니다. 기존 모듈에 함수만 더해진 경우에는 다시 설치하지 않아도 됩니다.

### 편집기 설정 (1.2절)

저장소 루트의 `.vscode/settings.json`은 이 프로젝트를 여는 모든 사람에게 같은 규칙을 적용합니다. 인터프리터 경로, 저장 시 자동 서식, 줄바꿈 문자와 인코딩이 고정되어 있어 운영체제가 달라도 결과가 갈리지 않습니다.

인터프리터 경로는 **윈도우 기준**으로 적어 두었습니다.

```jsonc
"python.defaultInterpreterPath": "${workspaceFolder}/.venv/Scripts/python.exe"
```

macOS와 리눅스에서 실습한다면 이 줄만 아래와 같이 바꿉니다.

```jsonc
"python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python"
```

설정이 적용되지 않는다면 `Ctrl+Shift+P` → `Developer: Reload Window`로 창을 새로 고치거나, `Python: Select Interpreter`에서 `.venv` 항목을 직접 선택하세요.

다음 확장을 함께 설치해야 설정이 온전히 동작합니다. 설치 전에는 `settings.json`의 서식 도구 지정 줄에 경고 표시가 나타나는데, 오타가 아니라 해당 확장을 찾을 수 없다는 뜻입니다.

| 확장 | 용도 |
|---|---|
| Python | 인터프리터 연동, 디버깅, 언어 서버 |
| Pylint | 코드 품질 검사 |
| Black Formatter | 저장 시 코드 서식 자동 통일 |
| Remote - SSH | 원격 서버 접속 개발(선택) |

### 원격 개발 환경 (1.2절)

소속 조직이 승인한 분석 서버에서 실습하는 경우 VS Code Remote-SSH로 접속한 뒤, 저장소 루트에서 다음을 실행해 현재 실행 위치를 확인합니다. 원격 서버가 없어도 모든 실습은 로컬에서 진행할 수 있습니다.

```powershell
python part1_python_automation\ch01\ch01_02_remote_check.py
```

세션 유형, 인터프리터 경로, 작업 디렉터리, 데이터 접근 가능 여부가 한 화면에 출력됩니다. 분석 결과가 재현되지 않을 때 가장 먼저 확인할 정보입니다.

### API 키 설정 (1.5절 / 12~13장 실습)

저장소 루트에 `.env` 파일을 만들고 키를 넣습니다. 이 파일은 `.gitignore`에 등록되어 있어 `git add`의 대상에서 빠집니다. 다만 키 관리 책임까지 대신하지는 않으므로, 키를 화면 캡처나 메신저로 공유하지 않습니다.

```
OPENAI_API_KEY=sk-...
```

키 발급과 결제 등록 절차는 **온라인 부록 B**에서 안내합니다. 1.5절 실습은 키가 없어도 진행할 수 있으므로, 결제 수단 등록은 12장에서 실제로 API를 호출할 때 해도 됩니다.

## 통합 데이터셋

`data/data_generator.py`를 실행하면 교육용 관계식으로 만든 5,000행 × 16열 CSV(`data/alphachip_v2_integrated_data.csv`)가 생성됩니다. 난수 시드가 고정되어 있어 **누가 실행해도 같은 데이터**가 만들어집니다.

### 구조

```
5,000행 = 10 로트 × 로트당 웨이퍼 5장 × 웨이퍼당 다이 100개
웨이퍼 1장 = 10 × 10 격자 (Die_X 0~9, Die_Y 0~9)
장비는 웨이퍼 단위로 배정됩니다(한 웨이퍼의 식각은 한 장비에서 처리).
```

한 행은 다이 한 개에 대한 통합 관측 레코드입니다. `Wafer_ID`는 로트마다 `W_00`부터 다시 시작하므로, 웨이퍼를 특정하려면 `Lot_ID`와 함께 씁니다. 다이 하나는 `Lot_ID`, `Wafer_ID`, `Die_X`, `Die_Y` 네 값으로 특정합니다.

### 컬럼

| 구분 | 컬럼 |
|---|---|
| 메타데이터 | Timestamp, Lot_ID, Wafer_ID, Die_X, Die_Y, Equipment_ID |
| 공정 관측 조건(FDC) | Chamber_Temp, Pressure, Gas_Flow |
| 설계 분석 조건 | Voltage (칩의 공급 전압을 가정한 값, 식각 장비의 전압이 아님) |
| 설계 지표(EDA) | Path_ID, Operating_Freq, Worst_Slack, Leakage_Power |
| 결과 지표 | Pass_Fail, Error_Code |

설계 지표는 설계 단계의 분석값을 교육용 연결 규칙에 따라 그 다이에 대응시킨 값이며, 제조된 다이에서 직접 측정한 값이 아닙니다. `Leakage_Power`에는 무작위로 주입한 결측 125행(2.5%)이 있고 4.3절 결측치 실습에 씁니다. 다른 컬럼에는 결측이 없습니다.

### 에러 코드

| 코드 | 조건 (반올림 전 값 기준) | 의미 |
|---|---|---|
| `NORMAL` | 정상 | 특이사항 없음 |
| `ERR-T101` | Worst_Slack < 0 | 타이밍 에러(슬랙 음수). 불량 판정 |
| `ERR-G202` | 양품 판정 + Gas_Flow < 88 sccm | 반응 가스 유량 저하 상태 경고 |

타이밍 불량 코드가 우선 기록됩니다. `ERR-G202`는 양품 레코드에만 붙으므로, 이 코드가 없다고 가스 유량 저하가 없었던 것은 아닙니다. 또 이 경고만으로 이후 장비 고장을 확정할 수는 없습니다. 불량 건수는 저장된 `Pass_Fail`로 셉니다(4.3절).

### 증상 지표 (1~5장 공개 범위)

| 항목 | 값 |
|---|---|
| 전체 불량률 | 16.08% (804행) |
| 로트별 불량률 추이 | LOT_00 0.2% → LOT_09 62.2% (중간에 내려가는 구간 있음) |
| 수집 구간 | 2026-01-01 08:00 ~ 2026-01-18 16:35 (전체 5분 간격) |

로트가 진행될수록 불량률이 전반적으로 오르지만 단조 증가는 아닙니다. 여기까지가 증상이며, 불량이 어디에 몰려 있고 무엇과 함께 움직이는지는 6장에서 데이터로 추적합니다.

### 가상 데이터 고지

이 데이터셋은 데이터 통합·정제·분석 기법을 학습하기 위해 설계한 합성 데이터입니다. 실존 기업의 공정 조건, 레시피, 수율 수치와 무관합니다. 변수 사이의 관계는 교육 목적의 가정에 따라 생성했으며, 실제 제조 공정의 물리 모델을 검증하거나 특정 장비의 운전 조건을 제시하기 위한 자료가 아닙니다. 기법을 익히는 데는 지장이 없지만, 분석 결론을 현장에 그대로 적용할 수는 없습니다.
